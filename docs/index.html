Getting started

Install

Link a pinned version. There is nothing to install and nothing to build.

yf.css is everything: tokens, base styles, layout and every component. It finds Inter and JetBrains Mono in fonts/ next to itself, so there is no second stylesheet and no font request to set up. yf.js is optional. Every component reads correctly without it; the script adds the theme switch, tabs, menus, dialogs, toasts, sortable tables, copy buttons, sparklines, charts and the topo field.

Every file under a version is served with open CORS and a one-year immutable cache, so an app on another subdomain loads them straight from here.

yf.js applies the saved theme the moment it runs. In <head> without defer that happens before first paint; with defer, a reader who chose dark can see one light frame on reload. This page loads it without defer for that reason.

yf runs under a strict content security policy: no inline script, no inline style, no eval, no innerHTML with data. This page is served with default-src 'none', script-src 'self' and style-src 'self', and it works. If you load it from here, your policy needs to allow this host:

Content-Security-Policy: style-src 'self' https://ds.yoanfaure.com; script-src 'self' https://ds.yoanfaure.com; font-src https://ds.yoanfaure.com

Pinned versions only

There is no latest alias, on purpose. A released version never changes: {{CDN}}/yf.css is the same file today and in five years, so a page that links it cannot break because yf moved. To upgrade, change the version in the URL, then look at the page.

Versions follow semver. Patch releases fix bugs. Minor releases add components, variants and tokens. Major releases may rename or remove classes, tokens, data attributes or JavaScript APIs. Before 1.0 a minor release may break things too. A fix never reaches a page that pins an older version; that is the trade.

Icon sprite

Icons are Phosphor Regular in one SVG sprite, icons/yf-icons.svg. Reference a symbol with <use>. An icon takes its size from CSS (1rem, or .yf-icon--sm, --lg, --xl) and its colour from the text around it. The whole set is in icons.

An icon beside text is decoration: aria-hidden="true". An icon on its own needs role="img" and an aria-label.

From another origin, yf.js brings the sprite in

Browsers refuse a <use> that points at another origin, so href="{{CDN}}/icons/yf-icons.svg#check" alone would not work from your app. yf.js handles it: when the page has a .yf-icon, it fetches the sprite that sits next to it, keeps only the drawing, and puts the symbols in the page once. Write <use href="#check">. A full sprite URL is rewritten to #check too, but the browser logs one refusal before that, so prefer the short form. Add the sprite's origin to your connect-src. To skip the fetch, set <html data-yf-icons="off"> and paste the symbols you use into the page, which is what Claude artifacts do.

Using yf in Claude artifacts

An artifact cannot load an external stylesheet: its content security policy allows stylesheets from Google Fonts only. So an artifact inlines yf.css in a <style> block and loads Inter and JetBrains Mono from Google Fonts.

The three @font-face rules at the top of yf.css point at fonts/ by a relative URL, which will not resolve in an artifact. Delete them from the inlined copy, and the Google Fonts families of the same names apply. Inline yf.js the same way if the artifact needs behaviour, and paste the sprite inline as shown in icon sprite.

The result is the same page. Only where the files come from changes.

Theming

Light and dark. The system decides, unless data-theme="light" or data-theme="dark" is set on <html>. With yf.js, a toggle sets it and remembers the choice in localStorage under yf-theme. The switch is one short cross-fade, and none when the reader prefers reduced motion. Try these; they change this page.

yf.theme.set('dark'); // 'light', 'dark' or 'system' yf.theme.toggle(); // flips between light and dark yf.theme.get(); // what the reader saved: 'light', 'dark' or 'system' yf.theme.resolved(); // what is shown: 'light' or 'dark' document.addEventListener('yf:theme', (e) => console.log(e.detail)); // { theme, resolved }

Tokens are set on :root, so a theme applies to the whole page; a section cannot take the other one.

Cascade layers

Everything yf ships sits in a cascade layer, in this order, weakest first: yf.reset, yf.tokens, yf.base, yf.layout, yf.components, yf.utilities. CSS that is in no layer beats every layer, whatever its specificity, so your app's CSS always wins. No !important, no selector arms race.

/* unlayered, so these win */ :root { --yf-radius: 6px; } /* change a token */ .yf-button { letter-spacing: 0.02em; } /* change a component */

Foundations

Colour

Ink on paper, in two themes. Nothing is coloured to look nice: the only colours in yf are the three status colours below. The primary action is solid ink, and focus is a 2px ink outline with a 2px offset.

Text needs 4.5:1 against paper and the edge of a control 3:1. Rules and fills are decoration, so they are quieter on purpose. Ratios are computed from the tokens in this release's yf.css, rounded down. --yf-primary is --yf-fg and --yf-on-primary is --yf-bg.

Status colours

Status only. Muted red, amber and green mean one thing: status. They appear on pills, errors, toasts, banner marks and chart thresholds. They are never decoration, never brand, and never alone: a status is always text plus a form, a label, an icon or a glyph.

toasts

Call yf.toast(). The region is created when the page loads, because a live region has to exist before it is filled. While a modal dialog is open the page behind it is inert, so toasts go to a region inside the dialog, above it and still clickable. A danger toast is role="alert". At most five show. The clock stops while the pointer or focus is on a toast.

yf.toast('Copied to the clipboard.'); yf.toast({ message: 'Report saved.', status: 'success', // 'info', 'success', 'warning' or 'danger' action: { label: 'Undo', onClick: () => restore() }, timeout: 8000, // ms; 0 keeps it until dismissed }); yf.toast.dismissAll();

tooltips

CSS only; the tip shows on hover and on keyboard focus. yf.js adds Escape to dismiss it and exposes it as the description. Placement is data-yf-tooltip-pos: top (the default), bottom, left or right. An input or an svg cannot have a tip of its own; wrap it.

Overlays

A dialog stops the page for a decision that cannot wait. A menu holds the actions for one thing. Tabs split one view into peers. Dialog and menu are the platform's own <dialog> and popover, so Escape, focus return and the top layer come free. The three overlays (these two and the toast) share one look: paper, a 1px ink edge and the overlay shadow.

Data

Tables hold records and stats hold one number each. Numbers are right-aligned and tabular, ids are mono, and a status is always text plus a form.

table

Ruled, no boxes. Click a header to sort: ascending, descending, then the original order; data-yf-sort-first="descending" on a header starts that column high to low. Numbers sort as numbers and text sorts naturally ("item 2" before "item 10"). Without yf.js the headers are plain. A text cell keeps 7rem so it never squeezes under a word or two; a cell with any data-type (yours too, such as pill or actions) sizes to its content, and --yf-cell-min on a column's cells changes the minimum. .yf-wide on the cells of the column that carries the sentence (a title) keeps 14rem. The .yf-table__empty row shows while no other row is visible, rows a filter has hidden included. A sticky-header wrap is 28rem tall; .yf-table-wrap--tall makes it 40rem. Put a wide table in a .yf-table-wrap that scrolls sideways, with tabindex="0" so the keyboard can scroll it.

Charts

Series are ink shades, and each shade has a dash pattern, so a chart reads in grey, in print and for colour-blind readers. Never rely on the shade alone, and never use colour for a series. Status colour marks a threshold only: a dashed danger line is a limit and nothing else, and a bar over it is labelled with its number.

Every shade stays above 3:1 against paper in both themes. The shades sit close together on purpose, so the dash tells series apart and a direct label or a legend key names them.

Charts are hand-made or script-made SVG. .yf-chart sets the type; .yf-chart-grid and .yf-chart-axis draw the frame; .yf-series-1 to -4 give a line its shade and dash and a shape its fill; .yf-chart-threshold draws a limit. Set stroke-width as an attribute. Give every chart a text alternative: an aria-label that says what it shows, and the numbers somewhere a reader can reach.

The legend reuses the series classes on a short line, so its keys carry the same dash. A shape over its limit takes fill="var(--yf-danger)" in place of a series class, and its value is printed above it.

yf.chart

yf.chart draws a line or bar chart from a spec, at the width it is shown. It chooses round tick numbers, thins the x labels to fit, moves the end labels of a line apart so none overlap, writes the aria-label from your data, and redraws when its box changes size, so the text stays 10px at any width. Put the spec in a JSON block inside a block element, and set data-yf-chart to line or bar:

The chart is drawn where the script block sits; the caption and anything else in the figure are yours. A bar past a threshold turns danger and always prints its number, as in the hand-made chart above. A chart that is hidden when the page loads, in a closed <details> or an inactive tab, draws when it gets a width. With no data it draws an empty frame.

From script, call yf.chart.line(el, spec) or yf.chart.bar(el, spec). Each returns { update(spec), destroy() }. update merges the keys you pass into the spec and redraws.

const chart = yf.chart.line(document.getElementById('trend'), { title: 'open findings by severity', labels: ['3 Aug', '10 Aug', '17 Aug'], series: [ { name: 'Critical', values: [12, 9, 7] }, { name: 'High', values: [30, 31, 24] }, ], thresholds: [{ value: 10, label: 'target 10' }], }); chart.update({ series: newSeries }); // merge into the spec, redraw chart.destroy(); // stop watching, remove the svg

States

The topo field, the ASCII contours from yoanfaure.com, appears in an app in three places only: empty states, loading states, and error pages. It is a watermark; text over it gets a halo of the page colour. The headline of an empty state invites; it never apologises. The field draws only while its box is on screen, pauses when the tab is hidden, shows one still frame under reduced motion, and a pointer over the box raises a gentle hill. yf.js is what draws it; without the script the box is empty and the text still reads.
